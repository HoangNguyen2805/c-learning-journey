# 7.6 - Error Handling - Stderr and Exit

## Big idea

Programs have TWO output streams for a reason:

```text
stdout  -> results (redirectable)
stderr  -> complaints (goes to the screen even when stdout is redirected)
```

```bash
./cat missing.txt > out.txt
```

If the "can't open" message went to stdout, it would vanish INTO out.txt — polluting the data AND hiding the error. Write errors to stderr:

```c
fprintf(stderr, "cat: can't open %s\n", *argv);
```

---

## The improved cat (book version 2)

```c
#include <stdio.h>

main(int argc, char *argv[])
{
    FILE *fp;
    void filecopy(FILE *, FILE *);
    char *prog = argv[0];            /* program name for messages */

    if (argc == 1)
        filecopy(stdin, stdout);
    else
        while (--argc > 0)
            if ((fp = fopen(*++argv, "r")) == NULL) {
                fprintf(stderr, "%s: can't open %s\n", prog, *argv);
                exit(1);
            } else {
                filecopy(fp, stdout);
                fclose(fp);
            }
    if (ferror(stdout)) {
        fprintf(stderr, "%s: error writing stdout\n", prog);
        exit(2);
    }
    exit(0);
}
```

Improvements over version 1:

1. messages → stderr, prefixed with the **program name** (`argv[0]`)
2. **exit status** signals success/failure to the caller

---

## exit and return codes

```c
#include <stdlib.h>
exit(0);        /* success                  */
exit(1);        /* failure (any nonzero)    */
```

- `exit(expr)` anywhere ≡ `return expr` in main
- exit **closes all open files** (flushing buffers) first
- the shell can test it: `./prog && echo worked`
- convention: 0 = OK; nonzero = kinds of trouble

---

## ferror and feof

```c
int ferror(FILE *fp);    /* nonzero if an ERROR occurred on fp */
int feof(FILE *fp);      /* nonzero if END OF FILE was reached */
```

Output errors are real (disk full!) but rarely checked; the book checks stdout once at the end. feof distinguishes "input ended" from "input broke" — both make reads return EOF.

---

## Sorting messages at the shell

```bash
./prog > results.txt            # stderr still visible on screen
./prog 2> errors.log            # redirect stderr alone
./prog > out.txt 2> err.txt     # separate both
```

(Shell syntax, not C — but it's WHY the two streams exist.)

---

## stderr is typically unbuffered

Messages appear immediately, even if the program crashes right after — another reason diagnostics belong there.

---

## Summary table

| Concept | Usage |
|---|---|
| Error messages | `fprintf(stderr, ...)` |
| Include prog name | `char *prog = argv[0];` |
| Success exit | `exit(0)` / `return 0` |
| Failure exit | `exit(nonzero)` |
| exit closes files | buffered output flushed |
| Stream error test | `ferror(fp)` |
| EOF vs error | `feof(fp)` vs `ferror(fp)` |
| Shell check | `prog && next`, `echo $?` |
