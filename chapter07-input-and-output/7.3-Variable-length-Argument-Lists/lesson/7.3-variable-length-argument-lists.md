# 7.3 - Variable-length Argument Lists

## Big idea

How does `printf` accept 1 argument... or 7? Its declaration ends with `...`:

```c
int printf(char *fmt, ...);
```

`<stdarg.h>` lets YOU write such functions. K&R demonstrates with **minprintf**, a tiny printf clone.

---

## The four tools of <stdarg.h>

```c
va_list ap;                 /* the argument-walking cursor           */
va_start(ap, lastnamed);    /* aim it after the LAST NAMED parameter */
type v = va_arg(ap, type);  /* fetch next arg AS 'type', advance     */
va_end(ap);                 /* clean up before returning             */
```

Rules:

- at least ONE named parameter must exist (you anchor va_start on it)
- each `va_arg` must name the arg's actual (promoted) type
- call `va_end` once you're done

---

## minprintf (the book program)

```c
#include <stdarg.h>

void minprintf(char *fmt, ...)
{
    va_list ap;
    char *p, *sval;
    int ival;
    double dval;

    va_start(ap, fmt);
    for (p = fmt; *p; p++) {
        if (*p != '%') {
            putchar(*p);
            continue;
        }
        switch (*++p) {
        case 'd':
            ival = va_arg(ap, int);
            printf("%d", ival);
            break;
        case 'f':
            dval = va_arg(ap, double);
            printf("%f", dval);
            break;
        case 's':
            for (sval = va_arg(ap, char *); *sval; sval++)
                putchar(*sval);
            break;
        default:
            putchar(*p);
            break;
        }
    }
    va_end(ap);
}
```

Walk: scan the format; plain chars pass through; on `%d`/`%f`/`%s` pull the next arg with the matching type.

---

## Default argument promotions

In the `...` region, small types are automatically widened by the caller:

```text
char, short  ->  int
float        ->  double
```

That's why minprintf's `%f` reads `va_arg(ap, double)` — a float argument ARRIVES as double. Similarly never `va_arg(ap, char)` — use int.

---

## Why the format string is essential

The callee cannot know how many args exist or their types — the format string IS the contract. Lie in the format (`"%d"` with a double passed) and va_arg misreads memory. Same reason printf warnings matter.

---

## vprintf family (used in 8.3's error function)

To FORWARD your `...` to printf, use the v-variants that take a va_list:

```c
void error(char *fmt, ...)
{
    va_list args;

    va_start(args, fmt);
    fprintf(stderr, "error: ");
    vfprintf(stderr, fmt, args);
    fprintf(stderr, "\n");
    va_end(args);
}
```

---

## Summary table

| Tool | Role |
|---|---|
| `...` | declares variadic tail |
| `va_list ap` | cursor over unnamed args |
| `va_start(ap, last)` | initialize after last named param |
| `va_arg(ap, T)` | fetch next as T, advance |
| `va_end(ap)` | cleanup |
| Promotions | char/short→int, float→double |
| Contract | format string tells count+types |
| Forwarding | vprintf/vfprintf/vsprintf take va_list |
