# 6.8 - Unions

## Big idea

A **union** holds different types **in the same memory**, one at a time:

```c
union u_tag {
    int ival;
    float fval;
    char *sval;
} u;
```

A struct with these members would allocate space for ALL of them. A union allocates space for the LARGEST — because only one member is alive at any moment.

```text
struct: [ ival ][ fval ][ sval ]     sum of sizes (+padding)
union:  [ ival/fval/sval overlap ]   size of biggest member
```

---

## Reading the right member is YOUR job

```c
u.ival = 42;
printf("%d", u.ival);     /* fine                  */
printf("%f", u.fval);     /* nonsense bits!        */
```

The rule: **read back the member you last stored**. The union doesn't remember which — so pair it with a type tag:

```c
struct {
    int utype;                    /* INT, FLOAT, or STRING */
    union {
        int ival;
        float fval;
        char *sval;
    } u;
} symbol;

if (symbol.utype == INT)
    printf("%d\n", symbol.u.ival);
else if (symbol.utype == FLOAT)
    printf("%f\n", symbol.u.fval);
...
```

This "tagged union" is how compilers store symbol values — and it's the ancestor of variant types in modern languages.

---

## Access syntax

Same as structs:

```c
u.ival            /* member of union          */
pu->fval          /* via pointer to union     */
symtab[i].u.sval  /* nested inside structs    */
*symtab[i].u.sval /* first char of the string */
```

Unions may appear inside structs and vice versa.

---

## What you can do with unions

Same rights as structs:

```text
assign / copy as a unit
take address with &
access one member at a time
```

Restrictions:

- may only be **initialized with a value of its FIRST member's type**:
  `union u_tag u = { 42 };  /* goes to ival */`
- no comparisons with `==`

---

## Alignment and size

```c
sizeof(union u_tag) >= size of largest member
```

Possibly rounded up for alignment. A union is aligned strictly enough for the most demanding member.

---

## Honest uses vs type punning

Legit: saving space when values are mutually exclusive (symbol tables, message payloads).

Sketchy: writing one member and reading another to peek at raw bytes ("type punning") — implementation-dependent per K&R. Fun for inspection demos, not for portable logic.

---

## Summary table

| Concept | Union behavior |
|---|---|
| Storage | all members share ONE spot |
| Size | largest member (+ alignment) |
| Valid read | last member written only |
| Tagged union | struct { type tag + union } |
| Access | `.` and `->`, like structs |
| Initialize | first member's type only |
| Copy/assign | allowed, as a unit |
| Compare | not with `==` |
