# 6.9 - Bit-fields

## Big idea

When storage is precious or you're matching hardware formats, you can pack multiple tiny values into one word. C offers two routes:

1. **Masks and bitwise operators** (portable, explicit)
2. **Bit-fields** (compiler does the packing)

---

## Route 1: the mask idiom (review of 2.9)

```c
#define KEYWORD  01     /* octal: bit 0 */
#define EXTERNAL 02     /* bit 1 */
#define STATIC   04     /* bit 2 */
/* or */
enum { KEYWORD = 01, EXTERNAL = 02, STATIC = 04 };

flags |=  EXTERNAL | STATIC;    /* turn ON  */
flags &= ~(EXTERNAL | STATIC);  /* turn OFF */
if ((flags & (EXTERNAL | STATIC)) == 0)   /* both off? */
```

Powers of two ⇒ each flag owns one bit.

---

## Route 2: bit-fields

```c
struct {
    unsigned int is_keyword : 1;
    unsigned int is_extern  : 1;
    unsigned int is_static  : 1;
} flags;
```

`: 1` means "this member is 1 bit wide". Usage looks like normal members:

```c
flags.is_extern = flags.is_static = 1;   /* set   */
flags.is_extern = flags.is_static = 0;   /* clear */
if (flags.is_extern == 0 && flags.is_static == 0) ...
```

No masks, no shifting — the compiler handles it.

---

## Wider fields

Fields can be any width up to a word:

```c
struct date_packed {
    unsigned int day   : 5;    /* 0..31   needs 5 bits */
    unsigned int month : 4;    /* 0..15   needs 4 bits */
    unsigned int year  : 12;   /* 0..4095            */
};
```

21 bits of data typically packed into a single 4-byte unit.

A field of width n stores values `0 .. 2^n - 1` (unsigned). **Overflow wraps silently**: storing 32 into a 5-bit field yields 0.

---

## The fine print (all implementation-dependent!)

K&R is emphatic — almost everything about bit-fields varies by machine:

```text
- packing order: left-to-right or right-to-left (endianness-ish)
- whether fields cross word boundaries
- sign of a plain 'int' field  -> declare unsigned int explicitly!
- fields have NO addresses: &flags.is_extern is ILLEGAL
- no arrays of bit-fields
```

Unnamed fields pad: `unsigned : 4;` skips 4 bits. Width `: 0` forces alignment to the next word boundary.

---

## Masks vs bit-fields: when to use which

| | Masks | Bit-fields |
|---|---|---|
| Portability | high | low (layout varies) |
| Readability | medium (idioms) | high (named members) |
| Addressable | yes (whole word) | no `&` on fields |
| Matching external formats | you control layout | compiler controls layout |

Rule of thumb: file formats / network packets ⇒ masks & shifts. Internal space saving ⇒ bit-fields are fine.

---

## Summary table

| Concept | Syntax / fact |
|---|---|
| Flag masks | `#define STATIC 04`, `x |= f`, `x &= ~f`, `x & f` |
| Bit-field | `unsigned int name : width;` |
| Range | 0 to 2^width - 1 |
| Overflow | silent wrap |
| No address | `&field` illegal |
| Padding | unnamed field; `:0` = align next word |
| Portability | packing order & sign are impl-defined |
