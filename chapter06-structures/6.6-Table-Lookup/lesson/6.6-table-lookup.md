# 6.6 - Table Lookup

## Big idea

K&R builds the core of a symbol table: store (name, definition) pairs, retrieve by name FAST. The data structure: a **hash table** — an array of linked lists.

```text
lookup("PI")   -> pointer to its entry, or NULL
install("PI", "3.14159") -> add or replace
```

This is how `#define` tables inside compilers work.

---

## The structure: array of chains

```c
struct nlist {                  /* one table entry */
    struct nlist *next;         /* next entry in this chain */
    char *name;                 /* defined name             */
    char *defn;                 /* replacement text         */
};

#define HASHSIZE 101
static struct nlist *hashtab[HASHSIZE];   /* pointer array, all NULL */
```

Picture:

```text
hashtab[0]  -> NULL
hashtab[1]  -> ["EOF"|"-1"] -> NULL
hashtab[2]  -> NULL
...
hashtab[57] -> ["PI"|"3.14"] -> ["MAX"|"100"] -> NULL   (a collision chain)
```

---

## The hash function

Turn a string into an index:

```c
unsigned hash(char *s)
{
    unsigned hashval;

    for (hashval = 0; *s != '\0'; s++)
        hashval = *s + 31 * hashval;
    return hashval % HASHSIZE;
}
```

- `unsigned` ⇒ never negative
- `% HASHSIZE` ⇒ always a valid index
- multiplying by 31 scrambles characters' positions
- Not the best possible hash — K&R says so — but short and effective

Two different names CAN hash to the same slot: a **collision**. Chaining (the linked list) resolves it.

---

## lookup

```c
struct nlist *lookup(char *s)
{
    struct nlist *np;

    for (np = hashtab[hash(s)]; np != NULL; np = np->next)
        if (strcmp(s, np->name) == 0)
            return np;          /* found     */
    return NULL;                /* not found */
}
```

The idiom `for (ptr = head; ptr != NULL; ptr = ptr->next)` is THE standard list walk — memorize it.

---

## install

```c
struct nlist *install(char *name, char *defn)
{
    struct nlist *np;
    unsigned hashval;

    if ((np = lookup(name)) == NULL) {          /* not found: new entry */
        np = (struct nlist *) malloc(sizeof(*np));
        if (np == NULL || (np->name = mystrdup(name)) == NULL)
            return NULL;
        hashval = hash(name);
        np->next = hashtab[hashval];            /* push onto chain head */
        hashtab[hashval] = np;
    } else                                       /* already there:      */
        free((void *) np->defn);                 /* free old definition */
    if ((np->defn = mystrdup(defn)) == NULL)
        return NULL;
    return np;
}
```

Note the **push-front** insertion: new node's next = old head; head = new node. O(1).

---

## Performance

```text
average: O(1) lookup/insert  (chains stay short if table sized well)
worst:   O(n) if everything collides into one chain
```

Compare: BST from 6.5 gives O(log n) but keeps order; hash gives O(1) average but NO ordering.

---

## undef (book exercise 6-2 area)

Removing an entry requires relinking the chain around it — the classic
"track the previous pointer" (or pointer-to-pointer) list deletion.

---

## Summary table

| Concept | Meaning |
|---|---|
| Entry | struct nlist { next, name, defn } |
| Table | `static struct nlist *hashtab[HASHSIZE]` |
| hash() | `*s + 31*hashval`, then `% HASHSIZE` |
| Collision | two names, same slot → chained |
| lookup | hash, then walk the chain with strcmp |
| install | lookup first; new ⇒ push-front; exists ⇒ replace defn |
| Average cost | O(1) |
| Worst cost | O(n) single chain |
| vs BST | hash: faster, unordered; BST: ordered, O(log n) |
