# 6.7 - Typedef

## Big idea

`typedef` creates a **new NAME for an existing type** — not a new type:

```c
typedef int Length;

Length len, maxlen;        /* exactly the same as: int len, maxlen; */
Length *lengths[10];
```

Think of it as declaring a variable, but the "variable name" becomes a type alias.

---

## Syntax pattern

Write a normal declaration, stick `typedef` in front, and the declared name becomes the type:

```c
int Length;                 /* Length would be an int variable   */
typedef int Length;         /* Length is now a synonym for int   */

char *String;               /* String would be a char* variable  */
typedef char *String;       /* String is now a synonym for char* */
```

Now:

```c
String p, lineptr[MAXLINES];    /* p and each element are char*  */
p = (String) malloc(100);
int mycmp(String, String);
```

Convention: typedef names get capitalized first letters.

---

## Typedef + struct: the classic combo

```c
typedef struct tnode *Treeptr;

typedef struct tnode {
    char *word;
    int count;
    Treeptr left;
    Treeptr right;
} Treenode;
```

Then:

```c
Treenode *talloc(void)
{
    return (Treeptr) malloc(sizeof(Treenode));
}
```

No more writing `struct tnode` everywhere. Note the tag `tnode` is still needed inside for the self-reference.

---

## Typedef with complicated types

Where typedef truly shines — function pointers:

```c
typedef int (*PFI)(char *, char *);
/* PFI = "pointer to function(char*,char*) returning int" */

PFI strcmp_p, numcmp_p;          /* two such pointers, readable! */
PFI table[10];                   /* vs: int (*table[10])(char*,char*) */
```

---

## typedef vs #define

```c
#define  Ptr  int *
typedef  int *Ptr2;

Ptr  a, b;     /* expands textually: int *a, b;   b is plain int! BUG */
Ptr2 c, d;     /* both c and d are int*           correct             */
```

Differences:

```text
typedef: handled by the COMPILER, understands declaration syntax
#define: dumb TEXT substitution by the preprocessor
typedef: can encode array/function-pointer types; #define can't safely
```

---

## Why use typedef?

K&R gives two reasons:

1. **Portability**: `typedef long ptrdiff_t;` — change one line per platform. This is exactly how `size_t`, `ptrdiff_t` work.
2. **Documentation/readability**: `Treeptr` says more than `struct tnode *`.

## Summary table

| Concept | Example |
|---|---|
| Alias a type | `typedef int Length;` |
| Alias a pointer | `typedef char *String;` |
| Struct combo | `typedef struct tnode { ... } Treenode;` |
| Struct pointer | `typedef struct tnode *Treeptr;` |
| Function pointer | `typedef int (*PFI)(char*, char*);` |
| Not a new type | pure synonym — mixes freely with original |
| vs #define | compiler-level, not text substitution |
| Purposes | portability + readability |
