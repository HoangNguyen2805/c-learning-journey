# 5.8 — Initialization of Pointer Arrays

## The Problem

You want a function that returns the name of a month (as a string), given a month number.

```c
char *name = month_name(3);  /* should be "March" */
```

**Naive approach:** Store all 12 month names in one char array. But that wastes space — some months are short ("Feb"), others long ("September").

**Better approach:** Array of pointers. Each pointer points to a string. No wasted space.

---

## The Solution: Static Array of Pointers

```c
char *month_name(int n)
{
    static char *name[] = {
        "Illegal month",
        "January", "February", "March",
        "April", "May", "June",
        "July", "August", "September",
        "October", "November", "December"
    };
    return (n < 1 || n > 12) ? name[0] : name[n];
}
```

### What's Happening

`static char *name[]` declares:
- `name` is an array
- Each element is a `char *` (pointer to char)
- The array is `static` (persists across function calls)
- The size is omitted (compiler counts initializers)

The compiler sees 13 string literals and creates 13 pointers.

**Each pointer stores the address of a string literal.**

---

## Key Point: Compiler Counts Initializers

You don't write `name[13]`. The compiler counts the braces `{...}` and fills in the size automatically.

```c
static char *days[] = {
    "Sunday", "Monday", "Tuesday", "Wednesday",
    "Thursday", "Friday", "Saturday"
};

/* Compiler knows days has 7 elements */
```

---

## Memory Layout

For `month_name`:

```
name[0]  ---->  "Illegal month"
name[1]  ---->  "January"
name[2]  ---->  "February"
name[3]  ---->  "March"
...
name[12] ---->  "December"
```

Each `name[i]` is a pointer (4 or 8 bytes, depending on architecture).

The strings themselves live in the program's read-only memory (the string literal pool).

**Total storage for pointers:** 13 × sizeof(char *) bytes (roughly 104 bytes on 64-bit).

**Storage for strings:** "Illegal month" + "January" + ... ≈ 100+ bytes.

**Compared to:** A fixed-width 2D char array like `char names[13][15]` would need 13 × 15 = 195 bytes (much of it wasted padding).

---

## Why `static`?

The `static` keyword means the array is initialized once and persists.

```c
char *month_name(int n)
{
    static char *name[] = { ... };  /* built once */
    return name[n];
}
```

Without `static`, the array would be (re)created on every function call — wasteful.

---

## Accessing Elements

```c
char *m = month_name(3);
printf("%s\n", m);  /* prints "March" */
```

`month_name` returns a pointer. `printf("%s\n", ...)` prints the string it points to.

---

## This Works Because Strings Are Pointers

In C, a string literal like `"January"` is a `char *` (pointer to the first character).

```c
"January"  ≡  address of 'J'
```

So assigning to an array of `char *` just stores addresses. No copying.

---

## Warning: You Can Change the Pointer, Not the String

Two different things can be "changed" here, and only one is legal.

```
name[1] = "Jan";     /* OK  — the POINTER now holds a different address */
name[1][0] = 'j';    /* BAD — tries to write into a string literal      */
```

String literals live in read-only memory. Writing into one is **undefined behavior** — on Mac and WSL it usually crashes with `Segmentation fault` (or `Bus error` on Mac).

Ask yourself every time: *am I moving an arrow, or editing what the arrow points at?*

```
name[1] ──X──> "January"     (arrow moved)
         └───> "Jan"

name[1] ────> "January"      (editing the target: NOT allowed)
               ^ can't touch
```

That's why careful code writes `static const char *name[]` — `const` makes the compiler stop you if you try to write into the string.

**Contrast with 5.7:** `char aname[13][15]` copies the characters *into* the array, so `aname[1][0] = 'j'` is perfectly legal there. Same-looking subscript, different memory rules.

---

## Two Ways to Know Where the Table Ends

**1. Count with `sizeof`** (only works where the array was declared, not inside a function that received it as a parameter):

```c
int n = sizeof(name) / sizeof(name[0]);   /* total bytes / bytes per pointer */
```

**2. End with a `NULL` sentinel** (works anywhere, like `'\0'` ends a string):

```c
static char *langs[] = { "C", "Python", "Rust", NULL };
```

The loop walks until it hits `NULL` — no count needed. This is exactly how `argv` is terminated (you'll see it in 5.10).

Question to think about: why does `sizeof(name)` give the wrong answer inside a function whose parameter is `char *name[]`? (Hint: 5.3 — what does an array name decay into when passed?)

## You Already Used This in 5.7

K&R's `daytab` is the same idea with numbers instead of strings:

```c
static char daytab[2][13] = {
    {0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31},
    {0, 31, 29, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31}
};
```

Both are **static tables initialized once with a brace list** — the only difference is that `daytab` stores the values themselves, while `name[]` stores addresses of values.

---

## Common Use Case: String Lookup Tables

Any time you need a small lookup table of strings, use this pattern:

```c
static const char *error_messages[] = {
    "No error",
    "File not found",
    "Permission denied",
    "Invalid argument"
};

printf("%s\n", error_messages[error_code]);
```

## Summary Table

| Aspect | Detail |
|--------|--------|
| Declaration | `static char *name[]` |
| Type | Array of character pointers |
| Size | Compiler counts initializers |
| Storage | Pointers stored contiguously; strings in read-only memory |
| Access | `name[i]` is a pointer; `*name[i]` is the first character |
| Benefit | No wasted space (vs fixed-width 2D char array) |
| Typical Use | Lookup tables, string constants, mapping numbers to names |
| Legal | `name[i] = "other"` (move the pointer) |
| Undefined behavior | `name[i][0] = 'x'` (write into a string literal) |
| Finding the end | `sizeof(name)/sizeof(name[0])` in scope, or a `NULL` sentinel |

---

## Key Insight

This is **not** a 2D array. A 2D array `char aname[13][15]` allocates 195 contiguous bytes.

An array of pointers `char *name[]` allocates 13 pointers (104 bytes) and relies on string literals elsewhere in memory.

They look the same (`name[i]` in both cases), but they're fundamentally different.

The next section (5.9) drills this distinction.
