# 5.12 - Complicated Declarations

## Big idea

C declaration syntax mimics usage — but combinations of `*`, `[]`, and `()` can get hairy:

```c
char (*(*x())[])()
```

This section teaches you to **read any declaration** with a simple rule, and shows K&R's `dcl` program that converts declarations to English.

---

## The golden rule: precedence

When reading a declaration, from the identifier outward:

```text
[]  and  ()  bind TIGHTER than  *
Parentheses ( ) can override, just like in expressions.
```

So:

```c
int *daytab[13];     /* daytab is: array[13] of pointer to int   */
int (*daytab)[13];   /* daytab is: pointer to array[13] of int   */
```

Without parens: `[]` grabs first → array of pointers.
With parens: `*` grabs first → pointer to array.

---

## The spiral / inside-out method

1. Start at the **name**.
2. Look **right** for `[]` (array of...) or `()` (function returning...).
3. Look **left** for `*` (pointer to...).
4. When you hit a closing `)`, jump out of the parens and repeat.
5. Finish with the base type.

### Worked examples

```c
char **argv
```
argv is: pointer to pointer to char.

```c
int (*comp)(void *, void *)
```
comp is: pointer to function(void*, void*) returning int.

```c
char (*(*x())[])()
```
x is: function returning pointer to array[] of pointer to function returning char.

```c
char (*(*x[3])())[5]
```
x is: array[3] of pointer to function returning pointer to array[5] of char.

---

## Classic pairs to memorize

| Declaration | English |
|---|---|
| `int *f();` | function returning pointer to int |
| `int (*pf)();` | pointer to function returning int |
| `int *a[10];` | array[10] of pointer to int |
| `int (*a)[10];` | pointer to array[10] of int |
| `int **pp;` | pointer to pointer to int |
| `int (*t[5])(void);` | array[5] of pointer to function returning int |

## K&R's dcl program

The book builds a recursive-descent parser matching this grammar:

```text
dcl:        optional *'s  direct-dcl
direct-dcl: name
            ( dcl )
            direct-dcl ( )
            direct-dcl [ optional size ]
```

Structure of the code:

```text
gettoken()  - lexer: returns NAME, PARENS, BRACKETS, or a character
dcl()       - counts leading *'s, calls dirdcl(), appends "pointer to"
dirdcl()    - handles name | (dcl) | trailing ()/[] suffixes
```

Key insight: `dcl` and `dirdcl` call each other — **mutual recursion** mirroring the grammar's own recursion. Each level of parentheses in the input becomes a level of recursion in the parser.

---

## Why typedef helps

Real code tames these with `typedef` (coming in 6.7):

```c
typedef int (*CmpFn)(void *, void *);
CmpFn table[10];     /* vs: int (*table[10])(void*, void*); */
```

## Summary table

| Rule | Effect |
|---|---|
| `[]`, `()` bind before `*` | read right before left |
| `(*name)` | forces "pointer to" first |
| read right: `[N]` | "array[N] of" |
| read right: `()` | "function returning" |
| read left: `*` | "pointer to" |
| hit `)` | pop out one paren level, continue |
| base type last | "...int/char/etc." |
| dcl program | grammar → mutually recursive parser |
