# 5.6 Pointer Arrays; Pointers to Pointers — Built From Scratch

If you read K&R's 5.6 and it did not land, that is expected. The section
introduces the idea and then immediately buries it inside a hundred-line program
using `getline`, `alloc`, `strcpy`, and quicksort all at once.

This file builds the same idea in seven layers, starting from something you
already know. Read it in order. Do not skip ahead.

Here is the sentence the whole section rests on. It will not mean much yet:

> **A row of arrows. Sorting rearranges the arrows. The strings never move.**

Come back and reread that line after Layer 4.

---

## Layer 1: A pointer is a variable holding an address

```c
char c = 'A';
char *p = &c;
```

Two variables exist here. `c` holds a character. `p` holds the address of `c`.

```
        c                    p
    +-------+           +----------+
    |  'A'  | <---------|   addr   |
    +-------+           +----------+
     0x1000               0x2000
                       (holds 0x1000)
```

The point to hold onto: **`p` is a variable in its own right.** It occupies
memory. It has its own address, 0x2000. It can be assigned to, copied, and
passed around like any other variable.

That fact is what makes everything below possible.

---

## Layer 2: A string is an address

```c
char *s = "hello";
```

The characters `h e l l o \0` sit somewhere in memory as six bytes. `s` holds
the address of the first byte.

```
        s
    +----------+        +---+---+---+---+---+----+
    |   addr   |------->| h | e | l | l | o | \0 |
    +----------+        +---+---+---+---+---+----+
```

**`s` is not the string. `s` is an arrow pointing at the string.**

When you write `printf("%s", s)`, printf follows the arrow and prints characters
until it reaches `\0`.

This is why `char *` is called a "character pointer" and not a "string type" —
C has no string type. It has addresses of characters, and a convention that a
`\0` marks the end.

---

## Layer 3: Pointers are variables, so you can have an array of them

Start with something ordinary:

```c
int nums[3];
```

Three int-sized boxes in a row. Nothing surprising.

Now apply Layer 1. Pointers are variables. Variables can be stored in arrays.
Therefore:

```c
char *words[3];
```

Three **pointer-sized** boxes in a row. Each box holds an address.

```c
words[0] = "banana";
words[1] = "apple";
words[2] = "cherry";
```

```
         words                    the strings, elsewhere
      +----------+
  [0] |   addr   |------------->  "banana\0"
      +----------+
  [1] |   addr   |------------->  "apple\0"
      +----------+
  [2] |   addr   |------------->  "cherry\0"
      +----------+
      contiguous                  scattered wherever
```

**This is the whole idea of section 5.6.** The array is a neat row of arrows.
What they point at is scattered around memory and does not have to be neat.

### Reading the declaration

Work outward from the name:

```
      words              words
     words[3]            is an array of 3
    *words[3]            pointers
char *words[3]           to char
```

"words is an array of 3 pointers to char."

The `*` does not attach to `char`. It attaches to what each element *is*.

### Two expressions to keep straight

| Expression | Type | Value |
|---|---|---|
| `words[1]` | `char *` | the address of "apple" |
| `*words[1]` | `char` | the character `'a'` |

`words[i]` is the whole string. `*words[i]` is its first letter.

## Layer 4: Why this is worth doing

Here is the payoff. Swap two entries:

```c
char *temp;

temp = words[0];
words[0] = words[1];
words[1] = temp;
```

```
   BEFORE                          AFTER
    +---------+                    +---------+
[0] |    *----+---> "banana"   [0] |    *----+---+   "banana"
    +---------+                    +---------+   |       ^
[1] |    *----+---> "apple"    [1] |    *----+---+-------+
    +---------+                    +---------+   |
                                                 +---> "apple"
```

**The strings did not move. Not one byte of text was copied.** Only the arrows
changed which way they point.

That swap costs 8 bytes copied on a 64-bit machine — and it costs 8 bytes
whether the strings are 3 characters long or 3000.

Compare with physically swapping the text:

```c
char temp[MAXLEN];
strcpy(temp, words[0]);
strcpy(words[0], words[1]);
strcpy(words[1], temp);
```

This copies every character, three times over. It also requires that every
string have room for the longest possible string, which wastes space on short
ones and breaks on long ones.

K&R's phrasing: sorting by pointers *eliminates the twin problems of complicated
storage management and the high overhead of moving the lines themselves.*

### K&R's own words on why this problem needs pointers

The book motivates the section this way. Chapter 3 sorted an array of integers
with Shell sort; Chapter 4 improved it to quicksort. The same algorithms work
here — except that text lines:

- are of **different lengths**, and
- unlike integers, **cannot be compared or moved in a single operation**

So you need a data representation that copes with variable-length lines
efficiently. That representation is the array of pointers.

K&R's framing of the storage: *if the lines are stored end-to-end in one long
character array, then each line can be accessed by a pointer to its first
character.* One block of text, a row of arrows into it. Keep that picture — it
is exactly what Exercise 5-7 asks you to build.

Now reread the sentence from the top of this file. It should mean something:

> A row of arrows. Sorting rearranges the arrows. The strings never move.

## Layer 5: `char **`

This is the part that trips everyone.

You already know that passing an array to a function converts it to a pointer to
its first element. Always. You have seen it:

```c
void f(int a[])     /* what you write */
void f(int *a)      /* what C actually gives the function */
```

Apply the identical rule to an array of pointers. What is the first element of
`char *words[]`? It is a `char *`. So a pointer to it is a pointer to a
`char *` — written `char **`.

```c
void writelines(char *lineptr[], int n)   /* what you write */
void writelines(char **lineptr, int n)    /* identical to the compiler */
```

Same declaration. Two spellings. Neither is more correct.

```
  lineptr  (char **)
     |
     v
  +---------+
  |    *----+---> "banana\0"      <-- this element is a char *
  +---------+
  |    *----+---> "apple\0"
  +---------+
```

`lineptr` points at the array. The array holds pointers. Hence
pointer-to-pointer.

### Peeling it back one layer at a time

```c
lineptr        /* char **  - points at the array         */
*lineptr       /* char *   - the first element, a string */
**lineptr      /* char     - the first character, 'b'    */
```

Each `*` removes one level of indirection. Count the stars in the type, count
the stars in the expression; they cancel.

### Which spelling to use

`char *v[]` tells a reader "this is an array of strings."
`char **v` tells a reader "this is a pointer to a pointer."

They compile identically, so choose the one that describes what you mean. For a
list of lines, `char *v[]` communicates better.

## Layer 6: `*lineptr++`

K&R writes `writelines` two ways. The straightforward one:

```c
void writelines(char *lineptr[], int nlines)
{
    int i;

    for (i = 0; i < nlines; i++)
        printf("%s\n", lineptr[i]);
}
```

And the pointer one:

```c
void writelines(char *lineptr[], int nlines)
{
    while (nlines-- > 0)
        printf("%s\n", *lineptr++);
}
```

Unpack `*lineptr++`. `++` binds tighter than `*`, and it is postfix:

1. Take the current value of `lineptr`
2. Dereference **that** — you get the `char *` sitting at the current position
3. Hand it to `printf`
4. **Then** advance `lineptr` one slot forward

```
   pass 1:                         pass 2:
               +---------+                     +---------+
   lineptr --> |    *----+--> "apple"          |    *    |
               +---------+                     +---------+
               |    *    |         lineptr --> |    *----+--> "banana"
               +---------+                     +---------+
   prints "apple", advances        prints "banana", advances
```

**Why this is safe:** `lineptr` is a *parameter* — a local copy of the caller's
pointer. Moving it forward does not disturb the array back in `main`.

Both versions are correct. K&R shows the pointer form because idiomatic C uses
it, and because it demonstrates that an array parameter really is just a
pointer. Write whichever you can read back in six months.

## Layer 7: The program

Three steps:

```
readlines   -> fill the array of arrows
qsort       -> rearrange the arrows
writelines  -> follow each arrow and print
```

The two size limits, and the array itself, live at file scope:

```c
#define MAXLINES 5000        /* max #lines to be sorted   */
#define MAXLEN   1000        /* max length of any input line */

char *lineptr[MAXLINES];     /* pointers to text lines */
```

`main` does nothing but coordinate:

```c
main()
{
    int nlines;

    if ((nlines = readlines(lineptr, MAXLINES)) >= 0) {
        qsort(lineptr, 0, nlines-1);
        writelines(lineptr, nlines);
        return 0;
    } else {
        printf("error: input too big to sort\n");
        return 1;
    }
}
```

### Why `readlines` returns `-1`

`readlines` can only cope with a finite number of lines — `MAXLINES` of them.
If the input has more, there is nowhere to put the extra pointers. So it returns
an **illegal count**, `-1`, which no valid line count could ever be. `main`
tests `>= 0` to tell success from failure. This is a common C idiom: overload
the return value with a sentinel that cannot be confused with a real answer.

### The part that confuses people: readlines

Per line, four things happen:

1. `getline` reads into a **temporary buffer** — the same buffer every iteration
2. Strip the trailing newline: `line[len-1] = '\0'`
3. `alloc` grabs **permanent storage** sized for this one line
4. `strcpy` copies temporary -> permanent, and the permanent address goes into
   `lineptr[nlines++]`

**Step 2 is not optional.** `getline` (from Section 1.9) returns the line *with*
its `\n` still attached, and returns the length including it. If you leave the
newline on, `strcmp` compares it as a real character, and your sort order goes
subtly wrong on lines that are prefixes of each other. Strip it once, at read
time, and everything downstream is clean.

**Steps 3 and 4 exist for exactly one reason.** Skip them and write this
instead:

```c
lineptr[nlines++] = line;   /* WRONG */
```

...and every arrow points at the same buffer:

```
      +---------+
  [0] |    *----+---+
      +---------+   |
  [1] |    *----+---+---->  line[]  (overwritten every iteration)
      +---------+   |
  [2] |    *----+---+
      +---------+
```

Print that and you get N copies of the last line read. **Every line needs its
own storage.** That is what the allocation is for.

### `alloc`, not `malloc`

K&R calls `alloc(int)` here — that is *their own* allocator from Section 5.4,
the `alloc` / `afree` pair that hands out chunks of one fixed buffer and frees
them in stack order. It is not `malloc`. In your own code `malloc` is the
practical choice, but keep the distinction in mind, because **Exercise 5-7 is
specifically about removing `alloc`** and having `main` supply the storage
instead.

### A precedence bug printed in the book

K&R's `readlines` as printed contains:

```c
if (nlines >= maxlines || p = alloc(len) == NULL)   /* BUG */
```

`==` binds tighter than `=`, so this parses as:

```c
p = (alloc(len) == NULL)
```

That assigns `0` or `1` to a `char *` and throws away the allocated address.
The condition needs its own parentheses:

```c
if (nlines >= maxlines || (p = alloc(len)) == NULL)   /* correct */
```

This is worth internalizing: **assignment has very low precedence.** Any time
you assign inside a condition, parenthesize it.

### The sort

The quicksort from Chapter 4, with two changes: the declarations, and the
comparison calls `strcmp`. The algorithm is untouched.

```c
/* qsort: sort v[left]...v[right] into increasing order */
void qsort(char *v[], int left, int right)
{
    int i, last;
    void swap(char *v[], int i, int j);

    if (left >= right)          /* fewer than two elements */
        return;
    swap(v, left, (left + right)/2);
    last = left;
    for (i = left+1; i <= right; i++)
        if (strcmp(v[i], v[left]) < 0)
            swap(v, ++last, i);
    swap(v, left, last);
    qsort(v, left, last-1);
    qsort(v, last+1, right);
}
```

Note the trap:

```c
if (strcmp(v[i], v[left]) < 0)      /* correct  */
if (v[i] < v[left])                 /* compiles, and is WRONG */
```

`v[i] < v[left]` compiles cleanly — it compares two *addresses*. It sorts by
memory position, which is roughly input order. A silent wrong answer, no
warning.

### The swap

```c
void swap(char *v[], int i, int j)
{
    char *temp;

    temp = v[i];
    v[i] = v[j];
    v[j] = temp;
}
```

`temp` is a `char *` because every element of `v` is a `char *`. Three pointer
assignments. This function is the entire section in six lines.

```bash
main
 |
 +-- readlines(lineptr, MAXLINES)  -> fills the array of arrows, returns count
 |
 +-- qsort(lineptr, 0, nlines-1)   -> reorders the arrows
 |        |
 |        +-- swap(v, i, j)        -> exchanges two arrows
 |        |
 |        +-- strcmp(v[i], v[j])   -> decides which comes first
 |
 +-- writelines(lineptr, nlines)   -> follows each arrow, prints
 ```

- `readlines` — the input half. Loops calling `getline` (your function from Ch.1), and for each line: strips the newline, allocates permanent storage, copies the line in, stores that address in `lineptr[i]`. Returns how many lines it read, or `-1` if there were too many.

- `writelines` — the output half. Walks the array and `printf("%s\n", ...)` each one. Three lines of code.

- `swap` — exchanges two entries in the array. Three assignments, `char *temp` in the middle. Called only by `qsort`.

- `qsort` — your quicksort from Chapter 4, unchanged except it calls `strcmp` instead of using `<`.

- So `swap` and `qsort` are the sorting half, `readlines` and `writelines` are the I/O half.

## Summary

| Concept | Form | Meaning |
|---|---|---|
| Array of pointers | `char *v[N];` | N arrows |
| One element | `v[i]` | a `char *` — a whole string |
| First character of it | `*v[i]` | a `char` |
| As a parameter | `char *v[]` = `char **v` | identical |
| Compare two lines | `strcmp(v[i], v[j]) < 0` | never `<` |
| Exchange two lines | swap the pointers | text does not move |
| Cost per swap | O(1) | one pointer copy |
| Cost of moving text | O(line length) | why we do not |
| Strip the newline | `line[len-1] = '\0'` | getline keeps the `\n` |
| Overflow signal | `return -1` | illegal count as sentinel |
| Assign in a condition | `(p = f()) == NULL` | parens are mandatory |
