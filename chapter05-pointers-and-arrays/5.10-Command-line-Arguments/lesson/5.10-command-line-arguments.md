# 5.10 - Command-line Arguments

## Big idea

Until now, `main()` took no arguments. But C lets programs receive input **from the command line** when they start:

```bash
./myprogram hello world 42
```

C passes these words into `main` through two parameters:

```c
int main(int argc, char *argv[])
```

```text
argc = argument count (how many words, including program name)
argv = argument vector (array of strings, one per word)
```

---

## What argc and argv contain

For `./myprogram hello world 42`:

```text
argc = 4

argv[0] = "./myprogram"   (program name itself)
argv[1] = "hello"
argv[2] = "world"
argv[3] = "42"
argv[4] = NULL            (guaranteed NULL terminator)
```

Key facts:

- `argv[0]` is always the program name
- Real arguments start at `argv[1]`
- `argv[argc]` is always `NULL`
- Every argument arrives as a **string** — even "42" is text, not a number

---

## argv is an array of pointers

`char *argv[]` means: an array of pointers to char.

```text
argv ──► [ptr0] ──► "./myprogram"
         [ptr1] ──► "hello"
         [ptr2] ──► "world"
         [ptr3] ──► "42"
         [ptr4] ──► NULL
```

This connects directly to 5.6 (pointer arrays). `argv` is exactly the same structure as `char *lineptr[]`.

---

## Echo: the classic example

K&R's version 1 (array subscript style):

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    int i;

    for (i = 1; i < argc; i++)
        printf("%s%s", argv[i], (i < argc-1) ? " " : "");
    printf("\n");
    return 0;
}
```

K&R's version 2 (pointer style):

```c
while (--argc > 0)
    printf("%s%s", *++argv, (argc > 1) ? " " : "");
```

`*++argv` means: advance argv to the next pointer, then dereference it to get the string. Since `argv[0]` is the program name, pre-incrementing skips it naturally.

---

## Converting string arguments to numbers

Arguments are strings. To use "42" as a number:

```c
int n = atoi(argv[1]);       /* string to int, from <stdlib.h> */
double d = atof(argv[2]);    /* string to double */
```

Always check `argc` first, or you'll dereference garbage:

```c
if (argc < 2) {
    printf("usage: %s number\n", argv[0]);
    return 1;
}
```

---

## Option flags (K&R pattern)

K&R's find program handles flags like `-x` and `-n`:

```c
while (--argc > 0 && (*++argv)[0] == '-')
    while ((c = *++argv[0]))
        switch (c) {
        case 'x': except = 1; break;
        case 'n': number = 1; break;
        default:  printf("illegal option %c\n", c); break;
        }
```

Two subtle expressions:

```text
(*++argv)[0]   advance to next argument, look at its first char
*++argv[0]     advance WITHIN current argument to next char
```

Precedence explains the difference: `[]` binds tighter than unary `*` and `++`.

---

## Common mistakes

```c
int main(int argc, char *argv[]) {
    printf("%s\n", argv[1]);      /* CRASH if no arguments given */
}
```

```c
int sum = argv[1] + argv[2];      /* WRONG: adding pointers, not numbers */
int sum = atoi(argv[1]) + atoi(argv[2]);   /* correct */
```

---

## Summary table

| Concept | Meaning |
|---|---|
| `argc` | count of command-line words (>= 1) |
| `argv` | array of pointers to argument strings |
| `argv[0]` | program name |
| `argv[1]` .. `argv[argc-1]` | actual arguments |
| `argv[argc]` | `NULL` |
| `atoi()` / `atof()` | convert string argument to number |
| `(*++argv)[0]` | first char of next argument |
| `*++argv[0]` | next char of current argument |
