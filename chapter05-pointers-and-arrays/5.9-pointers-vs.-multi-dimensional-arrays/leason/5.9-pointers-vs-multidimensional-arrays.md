# 5.9 — Pointers vs. Multi-dimensional Arrays

## The Confusion

Both of these look similar:

```c
int a[10][20];    /* 2D array */
int *b[10];       /* array of pointers */
```

Both allow `a[3][4]` and `b[3][4]` syntax.

**But they are fundamentally different.**

K&R says: "Newcomers to C are sometimes confused about the difference."

---

## The Key Difference

### True 2D Array

```c
int a[10][20];
```

**What happens at compile time:**
- Allocate 10 × 20 × sizeof(int) = 800 ints contiguously
- Memory is set aside **now** — all 800 slots exist

**Memory layout:**
```
Row 0: a[0][0]  a[0][1]  ...  a[0][19]
Row 1: a[1][0]  a[1][1]  ...  a[1][19]
...
Row 9: a[9][0]  a[9][1]  ...  a[9][19]
```

All contiguous in memory.

---

### Array of Pointers

```c
int *b[10];
```

**What happens at compile time:**
- Allocate 10 pointers (roughly 80 bytes on 64-bit)
- Pointers are **not initialized** — they point to garbage

**You must initialize them yourself:**

```c
int *b[10];
b[0] = malloc(20 * sizeof(int));  /* b[0] now points to 20 ints */
b[1] = malloc(20 * sizeof(int));  /* b[1] points to different 20 ints */
```

Or:

```c
int row0[20], row1[20], row2[20];
int *b[3];
b[0] = row0;
b[1] = row1;
b[2] = row2;
```

---

## Comparison Table

| Aspect | `int a[10][20]` | `int *b[10]` |
|--------|-----------------|-------------|
| Type | True 2D array | Array of pointers |
| Memory allocated | 200 ints (800 bytes) contiguous | 10 pointers (80 bytes) |
| When allocated | Compile time (automatic) | Compile time (pointers only) |
| Rows allocated | All 10 rows exist | None (must initialize yourself) |
| Row length | All rows = 20 (fixed) | Can vary per row |
| Initialization | Automatic at compile time | Manual (must point pointers) |
| Passing to function | Must specify column count `int a[][20]` | Can omit first dimension `int *p[]` |
| Access `[i][j]` | Points to fixed location | Points to wherever `b[i]` points |

---

## The Advantage: Variable Row Lengths

This is **the big reason** to use pointer arrays.

With a true 2D array, all rows must have the same length:

```c
char names[100][15];  /* 100 names, each up to 15 chars */
/* Wastes space: "Bob" only uses 4 bytes, but 15 are allocated */
```

With a pointer array, rows can vary:

```c
char *names[100];
names[0] = "Bob";           /* 4 bytes (+ null terminator) */
names[1] = "Alexander";     /* 11 bytes */
names[2] = "X";             /* 2 bytes */
/* No wasted space */
```

---

## Most Common Use: Strings

K&R emphasizes this is the **most frequent use** of pointer arrays.

```c
char *name[] = {
    "Illegal month",   /* 15 bytes */
    "January",         /* 8 bytes */
    "Feb",             /* 4 bytes */
    ...
};
```

Compare to:

```c
char aname[][15] = {   /* Fixed 15 bytes per row, wasteful */
    "Illegal month",
    "January",
    "Feb",
    ...
};
```

Pointer array saves space.

---

## Memory Picture

### 2D Array

```c
int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
```

Memory:
```
Address  Value
0x1000   1      <- a[0][0]
0x1004   2      <- a[0][1]
0x1008   3      <- a[0][2]
0x100c   4      <- a[1][0]
0x1010   5      <- a[1][1]
0x1014   6      <- a[1][2]
```

Contiguous block.

### Pointer Array

```c
int row0[3] = {1, 2, 3};
int row1[3] = {4, 5, 6};
int *b[2] = {row0, row1};
```

Memory:
```
Address      Value           Meaning
0x2000       0x3000          <- b[0] (points to row0)
0x2008       0x3010          <- b[1] (points to row1)

0x3000       1               <- row0[0]
0x3004       2               <- row0[1]
0x3008       3               <- row0[2]

0x3010       4               <- row1[0]
0x3014       5               <- row1[1]
0x3018       6               <- row1[2]
```

Two separate blocks: pointers in one place, data in another.

---

## Accessing Elements

Both syntaxes work the same:

```c
a[1][2]    /* true 2D: go to row 1, then column 2 */
b[1][2]    /* pointer array: go to b[1] (a pointer), then dereference + 2 */
```

But the mechanism is different:
- `a[1][2]` calculates: base + (1 × 20 + 2) × sizeof(int)
- `b[1][2]` calculates: *(b[1] + 2)

---

## Subtle Point: Passing to Functions

**True 2D array:**
```c
void process(int a[][20]) { }  /* Must specify column count */
void process(int (*a)[20]) { } /* Alternate syntax (pointer to array) */
```

**Pointer array:**
```c
void process(int *p[]) { }     /* First dimension can be omitted */
void process(int **p) { }      /* Alternate: pointer to pointer */
```

Why? A 2D array is a specific shape at compile time. A pointer array is just a pointer to pointers.

---

## The Bottom Line

**Use a true 2D array when:**
- All rows have the same length
- You know all dimensions at compile time
- You want contiguous memory

**Use a pointer array when:**
- Rows have different lengths
- You want flexibility
- Storing strings with variable lengths

---

## Summary Table

| Question | 2D Array | Pointer Array |
|----------|----------|---------------|
| What is it? | Array of arrays | Array of pointers |
| Memory layout | Contiguous | Fragmented (but flexible) |
| Row lengths | Fixed (all same) | Variable (can differ) |
| Allocate at compile time? | Yes, automatic | Only pointers (data is manual) |
| Best for strings? | No, wasteful | Yes, efficient |
| Access `[i][j]` | Arithmetic | Double dereference |

---

## Key Insight

The syntax `a[i][j]` works for both, but it means different things:

- For 2D arrays: **arithmetic** (compute address)
- For pointer arrays: **double dereference** (follow pointer, then offset)

Understanding this distinction separates novices from experienced C programmers.
