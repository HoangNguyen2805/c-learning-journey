# 5.11 - Pointers to Functions

## Big idea

In C, a function is not a value — you can't assign one to a variable. But the **address of a function** IS a value. You can:

- store it in a pointer
- pass it to another function
- call the function through the pointer

This lets you write **generic code**: one sort function that works with ANY comparison rule you hand it.

---

## Declaring a function pointer

```c
int (*comp)(void *, void *);
```

Read inside-out:

```text
comp                     comp is...
(*comp)                  ...a pointer...
(*comp)( , )             ...to a function taking two args...
(*comp)(void*, void*)    ...of type void* each...
int (*comp)(...)         ...returning int
```

The parentheses around `(*comp)` are **essential**:

```c
int (*comp)(void*, void*);   /* pointer to function returning int   */
int *comp(void*, void*);     /* function returning pointer to int!  */
```

`()` binds tighter than `*`, so without the parens, `*` attaches to the return type.

---

## Getting a function's address

The function name by itself IS its address (like array names):

```c
int numcmp(char *, char *);

int (*fp)(char *, char *);
fp = numcmp;        /* store address; no () means no call */
```

---

## Calling through the pointer

```c
result = (*fp)(a, b);    /* classic K&R style */
result = fp(a, b);       /* also legal in modern C */
```

K&R writes `(*fp)(a, b)` to make the indirection visible. Both work.

---

## The K&R qsort example

K&R's generic quicksort takes the comparison as a parameter:

```c
void myqsort(void *v[], int left, int right,
             int (*comp)(void *, void *));
```

Now ONE sort function handles both cases:

```c
myqsort((void **) lineptr, 0, nlines-1,
        (int (*)(void*,void*))(numeric ? numcmp : strcmp));
```

- Sorting text? Pass `strcmp`.
- Sorting numbers-as-strings? Pass `numcmp`.

The sort never needs to know HOW two elements compare — it just calls `(*comp)(v[i], v[left])` and checks the sign.

---

## void* : the generic pointer

Any pointer can be converted to `void *` and back. That's why the generic qsort uses `void *v[]` — it can sort pointers to anything. The comparison function casts back to the real type inside.

---

## numcmp (from the book)

```c
#include <stdlib.h>

int numcmp(char *s1, char *s2)
{
    double v1 = atof(s1), v2 = atof(s2);
    if (v1 < v2)  return -1;
    if (v1 > v2)  return  1;
    return 0;
}
```

Same contract as `strcmp`: negative / zero / positive.

---

## Arrays of function pointers

A dispatch table — pick a function by index instead of a switch:

```c
double add(double,double); double sub(double,double);
double (*ops[])(double,double) = { add, sub };

result = ops[i](x, y);
```

This is the seed of virtual tables, interpreters, and menu systems.

---

## Common mistakes

```c
fp = numcmp();      /* WRONG: calls numcmp now, stores its int result */
fp = numcmp;        /* right: stores the address */

int *f(void);       /* function returning int* - NOT a function pointer */
int (*f)(void);     /* pointer to function returning int */
```

## Summary table

| Concept | Syntax |
|---|---|
| Declare fn pointer | `int (*fp)(int, int);` |
| Assign | `fp = myfunc;` |
| Call | `(*fp)(a,b)` or `fp(a,b)` |
| As parameter | `void sort(..., int (*comp)(void*,void*))` |
| Array of fn pointers | `int (*table[4])(int);` |
| Generic pointer | `void *` converts to/from any object pointer |
| Contract like strcmp | return `<0`, `0`, `>0` |
